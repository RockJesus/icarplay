# 网页投屏（WebRTC）

> 适用版本 v0.9.9

## 是什么

车机当接收端，手机用浏览器投屏，**不需要手机装 App**：

1. 车机打开「网页投屏」，页面顶部显示一个地址，例如 `http://192.168.1.7:8180/send?t=xxxx`
2. 手机连同一个 Wi‑Fi，用**安卓 Chrome** 打开这个地址
3. 点「开始共享屏幕」并允许，画面就投到车机
4. 停止时手机会自动通知车机，页面回到等待状态

媒体流是 WebRTC 局域网直连（host candidate），信令只在车机本地跑一个纯 JDK socket 服务，**不出公网、不依赖 GMS、不上传云端**。

## 技术实现

| 组件 | 说明 |
|---|---|
| `MirrorServer` | `ServerSocket` 从 8180 起顺延 8 个端口；提供 `/car`（车机接收页）、`/send`（手机发送页）、`/ws`（自实现的 WebSocket 信令，帧解析 + SDP/ICE 广播） |
| `MirrorActivity` | 启动服务 + WebView 加载 `http://127.0.0.1:端口/car`，顶栏显示手机可访问的局域网地址，支持「复制地址 / 重连 / 返回」 |
| 令牌 | 每次打开生成 10 位随机 token，页面地址带 `?t=`，没有令牌一律 403，避免同一热点里别人乱连 |
| 并发限制 | 信令只允许 2 个连接（车机 + 一台手机），第三台会被直接断开 |

## 已联调验证

在本机用纯 JDK 跑通服务端，并用 Chromium 做了端到端测试：车机页收到 offer、回 answer、ICE 全部转发成功，接收页 `srcObject` 接管视频流，页面零 JS 报错。

## 已知限制（重要）

| 项 | 说明 |
|---|---|
| **iPhone 不支持** | iOS Safari 没有 `getDisplayMedia`，没法共享屏幕；iPhone 请继续用 AirPlay。这条链路只对**安卓 Chrome** 有效 |
| **必须同一局域网** | 车机和手机要在一个网段；没有外置路由器时，用手机开热点、车机连该热点即可 |
| **Chrome 版本** | 安卓 Chrome 需 72+ 才支持网页共享屏幕，建议用较新的 Chrome |
| **发热与延迟** | 屏幕采集 + H.264 编码在手机上跑，延迟约 100–300ms、手机会发热，适合导航/文档/视频，不适合玩游戏 |
| **WebView 能力** | 车机 8.1 的系统 WebView 要支持 `RTCPeerConnection`（Chromium 60+ 即可）；若接收页一直停在「等待手机连接」，先换新版 WebView 再试 |

## 与前几种投屏的分工

- **iPhone 投屏** → AirPlay
- **安卓投屏（不装 App）** → 本页网页投屏
- **车控/桌面投屏** → 后续的 VNC 客户端
- **文件传输** → 无线传文件
