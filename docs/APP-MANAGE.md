# 应用管理（卸载车机上的其它 App）

原生设置里卸载按钮是灰的、点不动？这一页把原因和动作都摊开：能卸的走系统确认框，卸不掉的告诉你去哪儿解。

`状态：已接入 v0.9.1`　·　`只列第三方应用 · 系统应用只能停用`　·　[← 返回 README](../README.md)

## 它做什么

| 动作 | 行为 |
|---|---|
| **卸载** | 调起系统卸载确认框（`ACTION_UNINSTALL_PACKAGE`）；确认后由系统删除，应用本身不静默删包 |
| **详情** | 打开系统的「应用信息」页，可以在那里「强行停止 / 停用 / 清除数据」 |
| **刷新** | 重新读取已安装列表 |
| 列表 | 只列**第三方应用**，系统预装应用不列（列了也卸不掉）；被占用的排在最前并标红原因 |

「小白点」这类悬浮工具 App 基本都会带一个无障碍服务，只要有服务在跑，系统就会拒绝卸载——这是 Android 的保护机制，不是 App 坏了。

## 卸不掉的三个常见原因

| 原因 | 现象 | 怎么解 |
|---|---|---|
| **设备管理员** | 卸载按钮灰，提示“此应用已被设为设备管理员” | 页内「设备管理员」→ 系统安全页 → 取消勾选 → 回来再卸 |
| **无障碍服务** | 卸载按钮灰，或卸完残留服务 | 页内「无障碍设置」→ 关掉该 App 的服务开关 → 回来再卸 |
| **系统预装** | 应用信息里「卸载」不可点 | 只能「停用」：详情页 → 停用（车机自带的百度 CarLife 就属于这类） |

车机上的实操顺序建议：先在应用管理页点「卸载」，系统会明确告诉你被什么拦住；按提示关掉对应开关，再卸一次即可。

## 与旧版小白点 / 旧 CarLife APK 的关系

- 旧小白点（自制悬浮球 App）卸掉后不影响 iCarPlay：iCarPlay 自带悬浮按钮，走无障碍悬浮层，不依赖任何外部悬浮球；
- 旧 CarLife 接收 APK 卸掉后，首页第五张卡 **CarLife+** 仍在同一个 `icarplay.apk` 里，功能不受影响；
- 车机**预装**的百度 CarLife 是系统分区应用，无法卸载，只能停用；需要时在系统设置里重新启用。

## 边界（重要）

- 第三方 App **没有**静默卸载别的应用的权限：Android 不允许，本页也不申请 `INSTALL_PACKAGES` / `DELETE_PACKAGES` 这类系统级权限；
- 卸载一定会在屏幕上弹系统确认框，确认动作永远在用户手里；
- 本页也不做“批量静默清理”，避免误删；
- 系统应用、正在运行的设备管理员、系统签名的应用无法被卸载，页面会给原因而不是假装成功。

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 点卸载没反应 | 该包不允许卸载（系统应用 / 设备管理员） | 看列表里的红色标记；改用「详情」→ 停用 |
| 卸载后图标还在 | 桌面缓存没刷新 | 重启车机，或在桌面下拉刷新 |
| 列表看不到想卸的 App | 它是系统预装应用 | 系统应用不列；去系统设置里停用 |
| 卸载成功但开机又回来 | 系统预装 / 被其它应用重新安装 | 属系统行为，停用是唯一稳定办法 |
