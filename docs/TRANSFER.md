# 无线传文件（手机 ⇄ 车机 APK 互传）

不用 U 盘：车机开一个小服务，手机浏览器打开地址就能把 APK 传进车机，也能把车机上的 APK 下载回手机。

`状态：已接入 v0.9.0`　·　`端口 8090 · 只收 apk / apks · 上限 260MB`　·　[← 返回 README](../README.md)

</div>

---

## 四种通道

| 通道 | 怎么走 | 谁在动 |
|---|---|---|
| **同一 Wi‑Fi** | 车机与手机连同一个 AP（外置路由也行），车机点「启动服务」，手机浏览器输地址 | 手机上传 / 下载 |
| **手机热点** | 手机开个人热点 → 车机加入（一键无线投屏向导第 2 步）→ 同上 | 手机上传 / 下载 |
| **车机热点** | 连接中心「开启车机热点」→ 手机连车机 → 同上 | 手机上传 / 下载 |
| **蓝牙** | 文件列表里点「蓝牙分享」，交给系统蓝牙发给已配对手机；手机往车机发，走系统蓝牙接收 | 系统蓝牙 |

蓝牙只做**发送**与**系统接收**：Android 没有给第三方 App 提供 OPP（蓝牙文件接收）服务端接口，应用无法自己挂一个“蓝牙收件箱”。所以真正双向、进度的传输走 Wi‑Fi / 热点通道，蓝牙作为没网时的兜底分享。

## 车机 → 手机

1. 打开「传文件」页，点「启动服务」；
2. 页面上会显示 `http://车机IP:8090`，点「复制地址」可以复制；
3. 手机浏览器打开这个地址，页面下半部分是「车机上的 APK」，点「下载」直接存到手机；
4. 车机每次进页面会把**当前这个包的 APK**复制一份到共享目录（`icarplay-<版本>.apk`），方便手机直接拿走最新版。

## 手机 → 车机

1. 同一个地址，页面上半部分点「选择 APK · 开始上传」；
2. 选中文件后自动上传，有百分比进度；
3. 传完会出现在车机「车机上的 APK」列表里，带大小与时间；
4. 在车机上点「安装」，走系统的安装确认框（需要时去系统设置里允许“未知来源”），确认后覆盖升级。

## 实现要点

| 项 | 说明 |
|---|---|
| 服务 | `FileTransferServer`，只依赖 JDK socket，不引第三方 HTTP 框架 |
| 路由 | `GET /` 手机页面 · `GET /api/list` 列表 · `GET /dl?name=` 下载 · `PUT /upload?name=` 上传 · `GET /health` 探活 |
| 端口 | 默认 8090，被占用自动顺延最多 8 个 |
| 限制 | 只接受 `.apk` / `.apks`，单文件 260MB，文件名做白名单清洗、同名自动加后缀 |
| 落盘 | `Android/data/com.rockjesus.icarplay/files/transfer/`（应用私有目录，不写车机公共目录） |
| 安装 | `ACTION_VIEW` + FileProvider，交给系统安装器；应用不申请系统级安装权限、不静默装包 |
| 生命周期 | 页面退出即停服务；不随开机自启，也不常驻后台 |

## 安全提醒

- 服务只在**局域网**内监听，同网段的设备都能打开这个页面；不要在公共 Wi‑Fi 下长期开着，用完点「停止服务」；
- 页面只收发文件，不提供浏览车机其它目录的能力；
- 装包一定会在车机上弹系统确认，看到不认识的 APK 直接取消。

## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 手机打不开地址 | 不在同一网段 / 车机没启动服务 | 看页面上的「运行中」，用连接中心确认 IP；改用手机热点让车机加入 |
| 上传卡住不动 | 手机切到蜂窝数据 / AP 隔离 | 关掉手机数据网络，关掉热点的 AP 隔离 |
| 提示“只接受 .apk / .apks” | 传了别的类型 | 先打包成 apk，或改名后在车机上重试 |
| 点安装被拒 | 系统禁止未知来源 | 系统设置里给 iCarPlay 或文件管理器打开“安装未知应用” |
| 蓝牙分享打不开 | 车机没装系统蓝牙分享组件 | 用 Wi‑Fi 通道，或在手机上用其它方式接收 |
