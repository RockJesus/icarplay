# 豆包（网页版接入）

> 适用版本 v0.9.8

## 为什么用网页而不是官方 App

豆包没有开放的语音对话 API，官方 App 又是竖屏手机设计、登录要输入手机号，车机输入法很难用。所以这里直接内嵌豆包网页版：

- 登录走**官方二维码**：页面自己弹出二维码，用手机豆包 App 扫一下就登录，应用完全不接触账号密码
- 登录态由 WebView 的 Cookie 保存，下一次打开还是登录状态
- 语音输入把**麦克风权限透传给网页**：网页里的话筒按钮能用，识别与对话都在豆包的服务器上完成
- 回复的声音由网页自己播放，不需要额外音频通道

## 使用

1. 悬浮按钮菜单 → **豆包**（或连接中心 → `豆包 ›`）
2. 首次进入等页面加载完，页面中间会出现二维码，用手机豆包 App 扫码
3. 登录后顶栏会从「未登录 · 手机扫码」变成「已登录 · Cookie 已保存」
4. 点网页输入框旁边的话筒说话；若弹出权限框，选允许
5. 顶栏：**刷新** / **首页** / **麦克风**（先授权）/ **返回**

## 已知限制

| 项 | 说明 |
|---|---|
| **麦克风归属** | 车机麦克风是否对第三方应用开放取决于 SYNC+ 固件；若点话筒没反应，说明该路音频被系统占用，只能文字输入 |
| **网页语音入口** | 豆包网页是否有话筒按钮由它当期版本决定，本应用只负责把权限放开 |
| **扫码登录** | 需要手机装豆包 App；若网页要求二次验证，按页面提示在手机上完成 |
| **横屏排版** | 网页按桌面 Chrome 渲染（已伪装 UA），1920×720 下是横向聊天布局，可正常使用 |
| **缓存** | 清除本应用数据会退出登录；正常退出页面不会 |

## 合规边界

- 不申请任何系统级权限，仅 `RECORD_AUDIO`（麦克风），且只在网页请求时弹出
- 不读取、不上传账号凭据；登录完全发生在豆包官方页面内
- 不注入脚本、不改页面逻辑，只做容器
